# 阶段一工单拆分

阶段一建议拆成 8 张工单。第 1 张先固定前后端和 CLI 之间的数据协议，后面的任务可以并行开发；第 8 张负责把所有部分接成真实闭环。

## 工单 1：定义检测任务协议和结果模型

目标：固定 Web、服务端和 CLI 之间的边界。

详细协议图和示例见 `ticket-01-protocol.md`。

内容：

- 检测任务状态：等待中、检测中、已完成、失败、已过期；
- 一次性令牌的字段和过期规则；
- 创建任务、上传结果、查询状态的请求和响应结构；
- 项目环境结果模型；
- 组件库识别结果模型；
- 支持性结论和错误码；
- 明确禁止上传源码、环境变量和完整配置文件内容。

验收：前端和 CLI 可以依据同一份 JSON Schema（数据结构约定）开发，不再自行定义字段。

依赖：无。

## 工单 2：实现检测任务服务

目标：让服务端可以创建检测任务、签发一次性令牌、接收结果并返回状态。

内容：

- `POST /api/scan-sessions`；
- `POST /api/scan-sessions/:id/result`；
- `GET /api/scan-sessions/:id`；
- 令牌短期过期和一次性消费；
- 结果大小限制；
- 重复上传、过期上传和非法任务的错误处理；
- 结果持久化。

验收：可以用 HTTP 客户端创建任务、上传一份模拟 JSON，并查询到完成状态。

依赖：工单 1。

## 工单 3：实现 Web 检测任务页面

目标：让用户从页面开始一次本地检测。

内容：

- 创建检测任务按钮；
- 显示一次性 CLI 命令；
- 复制命令；
- 轮询检测状态；
- 展示等待中、检测中、完成和失败；
- 展示技术栈、组件库和支持性结论；
- 展示失败原因和用户下一步处理建议。

验收：页面可以创建任务，复制命令，并在服务端收到模拟结果后自动显示报告。

依赖：工单 1、工单 2。

## 工单 4：搭建 CLI 执行器和回传能力

目标：建立用户本地执行的 CLI 基础。

内容：

- CLI 命令和参数解析；
- `--project`、`--token`、`--server` 参数；
- 当前目录和显式项目目录处理；
- 本地检测日志；
- 结构化结果上传；
- 上传失败时保存本地结果并支持重试；
- 不读取和不上传环境变量文件、源码正文和密钥。

验收：在测试项目目录执行命令，可以生成检测结果并上传到工单 2 的服务端。

依赖：工单 1；服务端接口可用后与工单 2 联调。

## 工单 5：实现基础项目环境检测

目标：判断项目是否满足 MVP 的技术和结构要求。

内容：

- 查找唯一项目根目录；
- 发现 workspace 或 monorepo 后直接阻止继续；
- 识别 npm、pnpm、yarn、bun 和 lockfile；
- 检测 React 及版本；
- 检测 Tailwind CSS 是否为 v4；
- 检测 `@import "tailwindcss"` 和主题 CSS 文件；
- 检测 CSS 文件是否被入口引用；
- 检测 ESLint 依赖、配置和可加载性；
- 输出每项检查的状态、版本、依据和修复建议。

建议使用 `semver`（版本比较工具）、`fast-glob`（文件扫描工具）、`PostCSS`（CSS 解析器）和 ESLint 官方 API（接口）。

验收：对成功项目、Tailwind v3 项目、缺少 ESLint 项目、找不到根目录项目和 monorepo 分别得到正确结论。

依赖：工单 1、工单 4。

## 工单 6：接入官方 shadcn 项目查询

目标：使用官方能力确认项目的 shadcn 配置和已安装组件。

内容：

- 将固定版本的 shadcn CLI 作为我们的 CLI 运行依赖；
- 通过子进程执行 `shadcn info --json --cwd <project-root>`；
- 解析官方 JSON；
- 记录 shadcn 配置、Tailwind CSS 文件、别名、预设和已安装组件；
- 官方 CLI 失败时返回明确错误；
- 不实现备用配置解析器。

验收：在 `F:\lint-shadcn-tailwind-test` 中成功识别 Tailwind v4、shadcn 配置和 Button、Card、Input。

依赖：工单 1、工单 4、工单 5。

## 工单 7：汇总检测结果和支持矩阵

目标：把基础环境检测和官方 shadcn 查询转换成用户能理解的结论。

内容：

- 合并两条检测链路的结果；
- 生成 `supported`、`partially_supported`、`unsupported`、`needs_action`；
- 列出检测到的其他组件库候选；
- 只有官方 shadcn 查询成功时才自动启用 shadcn 适配；
- 检测到其他组件库时标记当前 MVP 不支持；
- 生成可显示在页面上的修复建议。

验收：用户可以明确知道项目是否能进入主题配置，以及阻止继续的具体原因。

依赖：工单 5、工单 6。

## 工单 8：使用真实测试仓库完成端到端闭环

目标：验证从 Web 发起到本地 CLI 回传的真实流程。

内容：

- 使用 `F:\lint-shadcn-tailwind-test` 作为测试项目；
- Web 创建检测任务；
- 在测试项目目录执行 CLI；
- 本地检测 React、Tailwind v4、ESLint 和 shadcn；
- 通过一次性令牌上传结果；
- Web 轮询并显示结果；
- 验证网络失败、令牌过期、重复上传和 monorepo 阻止；
- 编写自动化集成测试。

验收：完整流程可以重复运行，且测试项目源码从未上传到服务端。

依赖：工单 2、工单 3、工单 4、工单 5、工单 6、工单 7。

## 推荐开发顺序

```text
工单 1
  ↓
工单 2 ─── 工单 3
  ↓          ↓
工单 4
  ↓
工单 5 ─── 工单 6
      \    /
       工单 7
          ↓
       工单 8
```

如果只有一个人开发，按 1 → 2 → 4 → 5 → 6 → 7 → 3 → 8 开始最顺畅。页面可以在接口稳定后再完善，不会阻塞本地扫描器的开发。

## MVP 明确不拆的内容

以下内容不属于阶段一工单：

- 组件级 contracts（组件约定）；
- `no-restyle`（组件样式重设检查）；
- 备用 shadcn 配置解析器；
- 多组件库适配；
- CI（持续集成）和编辑器插件；
- 源码上传和服务端源码扫描。
