# 阶段一：项目接入与主题定位

状态：工单一、二、四已有实现；工单五、六、七、三、八待完成。本次审核已收敛工单范围，未提前实现主题定位。

## 目的

在用户本地确认 `Tailwind CSS v4`（第四版样式框架）的安装版本，定位主题文件，查询主要组件方案，将结果返回网页，为之后建立完整设计体系做准备。

产品后续仍按“基础体系和语义映射 → 主题产物与规则配置 → 接入项目 → 执行检查 → 偏移报告”推进。阶段一只是接入准备，不代替体系编辑与规则生成。

## 已确定的交互

用户复制命令在项目目录执行；本地工具只回传结构化事实；网页轮询任务。上传使用十分钟有效的一次性令牌，成功后不可重复写入。

```mermaid
flowchart LR
    A[网页创建任务并显示命令] --> B[用户本地执行]
    B --> C[查样式框架版本和主题路径]
    C --> D[官方组件工具查询]
    D --> E[汇总为可配置状态]
    E --> F[保存快照并回传]
    F --> G[网页展示并确认主题和主要组件方案]
```

## 边界

- 只处理单应用，识别到多包仓库仍按已确认决定阻止继续。
- 不识别前端框架作为门槛，不检查源码代表文件。
- 不要求项目预先安装或配置代码检查器、设计体系检查插件。
- 主题定位优先采用已核实的官方实验性查询接口；固定版本，不执行规则。
- 查询到路径不等于证明所有页面都引用它，页面应提供确认；不做全项目引用审计。
- 未使用组件库与官方查询失败是不同状态。无组件库项目仍可进入基础体系配置。
- 不安装依赖、不改写项目、不解析完整设计令牌、不生成组件约束。

## 交接和状态

以共享协议第二版为当前数据契约，细节见工单一说明。状态只保留等待结果、已完成和已过期；本地错误在终端显示，未设置开始/失败上报接口时不伪造网页进度。

安装缺失、主题未找到、组件未查询都允许表示，不填写假版本、假路径。查询结果中的绝对路径须转换为项目相对路径。
