# 阶段一代码审核与消融记录

日期：2026-09-28。审核基准为首次产品代码之前的文档提交，比较当前全部产品代码，并以最近用户确认的产品分工作为需求依据。本次未开发工单五、六的真实检测。

## 需求轴

发现四组偏离：

1. 共享协议把特定前端框架、代码检查器可加载性、主题全局引用状态做成必填字段。
2. 工单五反复加入提前运行插件、代表文件和全项目引用审计。
3. 未实现的创建中、检测中、失败上报在文档里被当作已有能力。
4. 组件查询清单与组件治理发生混淆，可能把无组件库项目挡在体系配置之前。

本次处理：协议改为第二版，只保留接入事实；重写阶段说明、协议说明、任务清单和工单五范围。组件信息服务于语义预设，实际规则接入放到设计体系生成之后。

最重要的需求修正是“安装依赖和找到主题”不再等于“插件已运行并证明全项目合规”。

## 工程轴

发现并修复：

- 生成的命令没有服务地址，改端口后仍会访问默认地址；现在使用监听端口或显式公开地址，测试直接执行生成命令中的参数。
- 存储异常被统一转换为请求错误；现在请求校验错误返回 400，内部故障返回脱敏的 500。
- 相对路径校验接受上跳路径和驱动器相对路径；现在拒绝越界路径。
- 默认反射任意浏览器来源；现在默认关闭跨域，按实际网页来源配置。
- 服务退出时先关数据库再关请求入口；现在先停止网络服务，再关闭存储。

未发现独立仓库编码标准；可消融项按设计判断处理，不把代码风格当成硬性错误。后续只读复核未发现本轮新增高风险回归。

## 消融如何做

先运行原有类型检查和 23 项测试。然后删除不服务当前目标的设计，并补上新边界的验收测试。

| 删除项 | 对照结果 | 处理 |
|---|---|---|
| 框架必填、检查器执行事实、必填包管理器画像 | 缺依赖或无主题现在可诚实返回，创建上传查询仍通过 | 删除 |
| 主题已被全项目引用布尔值 | 定位结果可返回，无需伪造证明 | 删除 |
| 没有依据的组件可信度分数 | 保留名称、状态、依据已足够用于页面确认 | 删除 |
| 无调用的失败方法和未实现任务状态 | 服务端等待、完成、过期及本地错误仍成立 | 删除 |
| 未被调用的协议聚合导出 | 命名导出继续完成校验 | 删除 |
| 尚未发布的旧命令参数别名 | 服务端和本地工具统一任务参数后，安装包仍可执行 | 删除 |

再对需要保留的设计做破坏性对照：每次只临时修改一处，运行对应测试，最后恢复文件。

| 临时关闭的能力 | 实验观察 | 结论 |
|---|---|---|
| 上传确认丢失后的查询核对 | 服务端已保存，但客户端报告网络失败；原成功路径测试失败 | 必须保留 |
| 令牌只能提交一次 | 同一令牌再次上传被接收；重复提交拒绝测试失败 | 必须保留 |
| 数据库持久化，替换为内存数据库 | 重开存储后任务丢失；重启测试失败 | 必须保留 |

三项失败均为预期业务回归，不是构建或解析失败。实验全部恢复，最终完整测试通过。复现实验脚本和摘要位于研究目录的消融证据子目录。

## 验证结果

- 类型检查通过。
- 最终 36 项自动化测试通过，含命令真实进程和本机网络请求。
- 构建并打包成功，在独立测试项目重新安装成功。
- 使用服务端生成的命令参数完成演示上传，重复提交确认和数据库重开验证通过。
- 测试项目的包清单与锁文件未改动。
- 源码、临时令牌、结果缓存和数据库文件未进入提交。

这里只验证通信和接入结果结构，不宣称真实样式框架扫描、官方主题查询或组件查询已经实现。

## 兼容与剩余边界

结果协议升为第二版，旧快照需要重新生成；旧数据库结果保留，查询时明确提示协议不兼容。命令行未公开发布，因此移除旧参数而不是永久维护兼容分支。

保留三个接口、存储接口、内存测试实现、文件数据库、一次性令牌、请求限制、快照和重试。它们均已有明确用途，不为减少文件数而删除。

服务仍为本地开发形态，没有账户与项目访问控制；面向公网部署前需要独立处理。当前数据库消费流程按单进程同步服务运行，不将本次验证扩大为分布式并发保证。

此次消融没有声称“绿色测试证明任意逻辑都安全可删”。删除依据同时来自调用情况、用户范围和对应的运行验证。
