# 工单五：样式框架与主题路径

状态：已实现，并通过构建后的命令与独立测试项目安装包验证。2026-09-29。

## 目标

确认 `Tailwind CSS v4`（第四版样式框架）是否安装和实际版本，得到供之后设计体系接入使用的主题文件路径。

## 实现范围

1. 定位指定单应用项目，保留多包仓库阻断约定。
2. 从目标项目解析实际安装的样式框架版本，不把包清单版本范围当作安装事实，也不读取我们工具自身的依赖冒充用户依赖。
3. 使用固定版本 `@shadcn/lint`（设计体系检查插件）的实验性 `project.themeFileFor`（主题路径查询）取得路径，不运行插件规则或代码检查器。
4. 返回相对路径、查询结果和明确的未找到或查询失败原因。

官方查询从给定项目内路径定位上下文，配置优先、自动发现补充；自动发现可能在多个入口中择一。这里返回的是查询选中的路径，不是全项目真实使用证明；由后续页面让用户确认。

为了查询而给我们的工具加入插件依赖，不等于要求用户先在项目安装、配置或运行它。

## 不做

不检查前端框架，不检查代码检查器安装或配置，不做代表文件探测、全项目引用审计、完整设计令牌解析或主题文件写入。不重写官方完整主题发现过程；接口变动通过锁版和回归处理。

## 验收

- 已安装第四版、未安装、其他版本和无法解析均有明确结果。
- 已有组件配置、无配置但有主题、找不到主题以及配置路径失效可被验证。
- 查询过程不执行源码规则，不改项目；路径来源如实表达，不把选中路径称为唯一正确。
- 缺失值用空值及状态表示，不要求伪造前端框架或检查器字段。

主题查询依据见插件能力审计；该接口确实公开且已实测。此前“没有接口，只能做规则探测”的判断撤回。

## 验证

自动化测试覆盖项目定位、多包阻断、实际安装版本、未安装、其他主版本、损坏版本、`.pnp.cjs` 无法确认、有无组件配置、主题缺失、多主题自动选择、越界路径和查询失败。构建后的命令把这些结果保存为快照并上传；组件方案保持未查询。

独立测试项目先安装本地压缩包，再执行真实查询。服务端收到该项目实际安装的第四版版本和组件配置中的主题路径。上传不包含令牌或项目绝对路径，项目清单和组件配置保持不变。
