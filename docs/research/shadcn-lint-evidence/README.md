# 发布包能力复现实验

日期：2026-09-28。测试对象：`@shadcn/lint@0.2.0`（设计体系检查插件发布版），配合 `eslint@10.11.0`（检查宿主）、`@typescript-eslint/parser@8.70.1`（源码解析器）和 `tailwindcss@4.3.3`（样式框架）。

这是隔离样例，不是产品规则配置。为了研究全部能力，样例开启全部六条规则；产品不因此启用组件约束。

在新的空研究目录安装上面的四个固定版本，把同目录的 `audit.mjs`（复现脚本）复制进去，然后执行 `node audit.mjs`（运行复现实验）。不要在用户实际项目运行；脚本会创建样例源码、主题和组件配置，并拒绝覆盖已有源码目录或组件配置。

脚本将结构化结果写到父目录的 `results.json`（结果记录）。本目录保存的是此次实测结果，主题路径已改为样例相对路径，不包含本机绝对路径。

十五项样例涵盖主题工具类、任意值、派生间距、原始色、未知令牌、未声明变量、基础颜色、普通样式类、拼写错误、内联样式、自定义属性、普通元素动态类、组件动态类、组件重设样式和样式标签。另检查项目查询接口、自动修复行为及禁止自定义属性配置的实际表现。

成功结果表示脚本执行完成，不代表所有样例都应该被拦截。哪些通过、哪些报错须阅读结果记录和上级能力审计文档。

另外在独立进程中只导入插件的 `project`（项目查询接口），调用 `themeFileFor`（主题路径查询）和 `colorTokensFor`（颜色令牌名称查询），成功得到主题路径和颜色名称；该过程没有启动代码检查器或执行规则。查询参数是项目内文件路径，用于确定项目上下文，不等于必须读取并检查该文件。
