# 设计体系护栏 MVP 产品流程

## 1. MVP 目标

用户在 30 分钟内完成：创建项目 → 配置设计体系底座 → 配置项目语义 → 生成规则包 → 接入真实 Tailwind 项目 → 运行检查 → 查看第一份偏移报告。

MVP 的产品定位是：

> 将设计体系底座和项目语义转换成 Tailwind 主题、组件库变量和可执行的代码检查配置。

MVP 使用 `@shadcn/lint` 作为检查执行底座，产品负责主题编辑、语义映射、规则包生成、项目接入和报告展示。

## 2. 支持范围

### 2.1 技术范围

- React
- Tailwind CSS v4
- ESLint
- `@shadcn/lint`

### 2.2 组件库范围

- `shadcn/ui`：MVP 完整支持，作为第一个组件库适配器；
- 暂不使用组件库：支持基础 Token 和项目语义；
- 其他组件库：MVP 可登记，但完整适配放到后续阶段。

### 2.3 设计体系范围

基础令牌支持：

- 颜色阶梯；
- 间距阶梯；
- 字号和字重；
- 圆角；
- 阴影。

项目语义支持：

- `primary`、`secondary`；
- `background`、`foreground`；
- `muted`、`border`；
- `destructive`；
- 用户自定义的少量语义角色。

## 3. 用户流程

### 第一步：创建项目

用户填写项目名称，选择 React 和 Tailwind CSS v4。

系统创建项目配置，并准备一套完整的 Tailwind 基础尺度。

### 第二步：选择组件库

用户选择主要组件库：

- `shadcn/ui`；
- 暂不使用组件库；
- 自研组件库登记。

选择 `shadcn/ui` 后，系统自动加载 shadcn 的语义预设和组件约定。用户不需要从空白建立语义层。

### 第三步：编辑设计体系底座

系统展示完整的基础阶梯。用户可以查看、修改和增加 Token：

- 颜色；
- 间距；
- 字号；
- 圆角；
- 阴影。

基础层是设计体系的可用范围。已被语义或组件使用的 Token 不能直接删除，修改或删除时需要展示影响范围。

### 第四步：配置项目语义

系统把组件库预设作为项目语义的初始内容。

用户修改的是“项目语义到基础 Token 的映射”，例如：

```text
primary → blue-600
secondary → violet-500
background → neutral-50
```

用户也可以增加少量自定义语义，例如 `brand`、`surface-elevated` 或 `status-success`。

组件库兼容变量由系统自动生成，不要求用户重复配置。

### 第五步：预览主题和组件

系统提供 Button、Card、Input、Alert 等组件预览，并支持浅色和深色模式。

用户修改基础 Token 或语义映射后，可以直接看到组件效果变化。

### 第六步：生成主题和规则包

系统生成：

- Tailwind `@theme`；
- 项目语义 CSS 变量；
- 组件库兼容变量；
- ESLint 配置；
- `@shadcn/lint` 规则；
- 组件 contracts；
- AI 项目规则说明。

默认规则包括：

- `no-arbitrary-values`；
- `no-raw-colors`；
- `no-unknown-classes`；
- `require-static-classes`；
- `no-restyle`。

规则默认由产品生成。用户可以调整规则级别、添加目录例外和补充自定义组件约定。

### 第七步：接入真实代码仓库

用户下载规则包，或通过 CLI 接入本地项目。

CLI 先检测：

- 是否使用 Tailwind CSS v4；
- 主题文件是否已经引入；
- Tailwind 是否扫描到源码；
- 组件库是否被识别；
- 规则配置是否完整。

主题没有真正接入时，CLI 报告“主题未接入”，不生成误导性的检查结果。

### 第八步：运行检查

用户运行：

```bash
npx design-guardrails check
```

检查内容包括：

- 任意值；
- 原始颜色；
- 未知工具类；
- 动态类名；
- 组件样式错误覆盖；
- 不符合组件 contracts 的写法。

### 第九步：查看偏移报告

报告展示：

- 偏移数量；
- 偏移类型；
- 文件和代码位置；
- 问题原因；
- 推荐替代方案；
- 已修复和仍存在的问题。

用户修改代码后重新运行检查，直到结果通过或进入可接受状态。

## 4. MVP 页面

1. 项目创建和环境检测；
2. 设计体系底座编辑；
3. 项目语义映射；
4. 主题和组件预览；
5. 规则包生成与接入指引；
6. 偏移报告。

## 5. MVP 完成标准

- 用户可以在 30 分钟内完成一次项目配置；
- 基础 Token、项目语义和组件库变量可以生成；
- 规则包可以接入一个真实 Tailwind CSS v4 项目；
- CLI 可以完成环境检测和检查；
- 系统可以展示第一份可读的偏移报告；
- 用户修改代码后可以再次检查并看到结果变化。

## 6. MVP 暂不包含

- Figma 自动同步；
- GitHub 自动连接；
- 多组件库同时适配；
- CI 集成；
- VS Code 或 Cursor 扩展；
- 自动修复代码；
- Vue、Svelte 等其他框架；
- 设计体系质量评估；
- 自研完整 Linter。

## 7. 后续阶段

第二阶段增加其他组件库适配器、CLI 的 CI 模式、规则版本管理、历史趋势和更完整的 Token 导入。

第三阶段增加编辑器扩展、团队策略、实时诊断、多框架支持和更丰富的自动修复能力。
